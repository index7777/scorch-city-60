# 灼城 60 — 居民視角完整重設計方案

狀態：Approved design direction / implementation in progress

核心原則：玩家不是城市管理者，也不是一開始就知道主線答案的任務執行者。玩家只是住在耐熱屋裡的一名居民；所有資訊、命名、UI 與教學都必須符合「我怎麼知道這件事？」這個問題。

## 1. 設計目標

1. 把全知視角改成有限知識視角。
2. 把「系統告訴你正解」改成「玩家從廣播、親眼觀察與他人說法拼湊世界」。
3. Day 1 只公開世界廣播已宣布的災害節奏，不公開中央站、冷源核心、終局工程與完整 NPC / 聚落資訊。
4. 所有未知地點、人口、資源、設備、人物與主線情報遵守 fog-of-war 規則。
5. UI 語言從城市管理儀表板改成個人生存日誌與可驗證資訊。
6. 不以 emoji 作為正式 UI icon。需要正式 icon 或美術資產時，使用生成式美術流程產製並納入 assets。

## 2. 資訊揭露三層架構

### 2.1 廣播層

Day 1 全城共知，只包含：

- Day 1–7：夜晚 8h，白晝 72°C。
- Day 8–14：夜晚 6h，白晝 78°C。
- Day 15–21：夜晚 4h，白晝 84°C。
- Day 22–29：夜晚 2h，白晝 92°C。
- Day 30 起：夜晚 0h，100°C 永晝。
- Day 60 是已知期限。
- 後續可由階段性廣播追加公開資訊。

廣播不能預先揭露：中央通風站、冷源核心、十階段工程、特定 NPC、聚落庫存、終局解法。

### 2.2 親眼層

玩家可直接確認：

- 耐熱屋與自己的庫存。
- 自己的身體狀態。
- 已實際偵察或搜索地點的可見資訊。
- 已親自接觸的具名 NPC。
- 自己搬回、使用、修復或安裝的物件。

### 2.3 傳聞層

來自 NPC、廣播追加訊息、環境痕跡或玩家推測。

每筆情報最終應保存：

- sourceType: broadcast / observed / rumor
- sourceName
- confidence
- heardDay
- subject / location
- content
- verified

正式視覺 icon 尚未加入前，先以文字來源標籤呈現；不得以 emoji 代替正式 icon。

## 3. HUD 重構

### 3.1 頂部主 HUD

保留：

- Day X / 60
- 時段與可用時間
- 屋內 / 屋外環境溫度

新增玩家個體狀態：

- hydration 水分
- satiety 飽足
- stamina 體力
- health 健康
- bodyTemp 體溫
- heat 熱累積（外勤用）

移除「基地續航 X 天」作為主要全局判斷；玩家應看到自己的狀態與自己知道的物資。

### 3.2 廣播節奏卡

主 HUD 顯示公開節奏：D8 / D15 / D22 / D30，以及對應 6h / 4h / 2h / 永晝、78 / 84 / 92 / 100°C。

### 3.3 耐熱屋卡

只呈現玩家親眼可知的起點資訊，例如供電、屋內狀況與自己的庫存入口。

### 3.4 認識的人

分開計算：

- 已親自接觸的具名人物。
- 只聽說有人活動，但尚未見過的人。
- 已接觸群體／聚落。

不得把尚未接觸的 NPC 或聚落人口直接算進 HUD。

### 3.5 冷源核心 / 中央站

Day 1 完全隱藏。

首次由文件、可信 NPC 或實際探索解鎖後，才顯示「你正在拼湊的線索」；進度細節依情報逐步揭露，不直接顯示 0/10。

## 4. 教學重構

### 4.1 開場

只交代：

- 玩家在耐熱屋醒來。
- 玩家不熟悉城市。
- 世界廣播反覆宣布 60 天、夜晚縮短、溫度升高、Day 30 永晝。
- 廣播沒有告知解法、倖存者數量或城市主線。

不得出現「修復城市」「中央安全區」「冷源核心十階段」等劇透。

### 4.2 教學提示

移除 STEP X / Y。

改成物理需求導向：

- 水不夠：提示要找水，不指定便利商店。
- 搬運效率差：提示可能需要推車或載具，不指定五金行。
- 高溫壓力：提示尋找降溫方式，不直接指定冷卻背包。

## 5. 外出行動中心

1. 一般目標選單只列已偵察地點。
2. 未偵察地點只能從地圖未知區域發起偵察行程。
3. 偵察行程只顯示未知風險與方向／距離等已知內容，不能洩漏 true name、loot、NPC、population、large asset。
4. 地點資訊使用「你稱之為 X」等有限知識命名。
5. 快速搜索與完整行程繼續維持資訊深度差異。

## 6. 聚落 / 人物資訊三段式解鎖

### Stage 0 — 未偵察

完全不出現在人物／群體面板。

### Stage 1 — 偵察過、未接觸

只能呈現環境痕跡，例如：

- 有人活動的跡象。
- 物資被移動過。
- 尚未親眼確認任何人。

### Stage 2 — 接觸至少一名 NPC

可顯示：

- 已接觸具名 NPC。
- NPC 對附近其他人的模糊描述。
- 來源、可信度、聽到的日期。

不能直接把未見過的人口數當作親眼事實。

### Stage 3 — 高信任／驗證

才可顯示較精確的群體規模與庫存估計，並標明來源。

移除 stable / unstable 這類上帝視角標籤，改用人物自己的描述。

## 7. 玩家個體狀態

新增持久化 state.player：

```js
player: {
  hydration: 100,
  satiety: 100,
  stamina: 100,
  health: 100,
  bodyTemp: 36.5,
  heat: 0
}
```

第一階段先完成：

- HUD 顯示。
- 存檔遷移。
- 基礎時間消耗與每日代謝。
- 低水分／低飽足對健康的基礎傷害。

後續完成：

- 遠征逐時熱累積。
- 冷卻設備、載具、環境溫度對 bodyTemp / heat 的影響。
- 明確死亡原因。

## 8. 水雙用系統

後續新增：

- drinkingPool
- coolingPool

玩家可調整預留比例。外勤冷卻池耗盡時，不應默默消耗飲用水；若允許自動動用，必須有明顯危險提示與玩家設定。

## 9. 電力系統

建立「你的電力」獨立視圖：

- 電池庫存 kWh
- 耐熱屋慢速供電
- 工具電量
- 充電時間
- 工具續航
- 未充電原因

電池不再只是與食物、水並列的普通資源；它是所有主動工具的能源貨幣。

## 10. 大型物件與載具

### 大型物件

分開顯示：

- 已發現
- 已搬回
- 公共資料估計總數（若玩家確實取得此公共資訊）

每個大型物件需顯示地點、估計重量、搬運需求與目前可否搬運。

### 載具

建立獨立視圖：徒手、推車、車、卡車。

必須明示：速度、載重、白晝耐受、燃料需求、是否能搬大型物件。

## 11. 日誌取代管理簡報

「每日簡報」改成「你的日記」。內容組成：

- 你自己的狀態。
- 昨天親眼看到／做過的事。
- 廣播內容。
- 聽到的傳聞。
- 玩家可合理推導的短期感受。

移除「事件鏈」「終局時程」「暫停遷入」等城市管理命令語言。

## 12. 命名重整

- 每日簡報 → 你的日記
- 城市動態 → 你聽到的與你做過的
- 已知倖存人口 → 你認識的人
- 聚落 / 避難點 → 尚未接觸時不出現；接觸後使用「你在 X 遇到的人們」
- 冷源核心主線 → 中期解鎖後「你正在拼湊的線索」
- 中央站容量 → 中期解鎖後「中央站可容納」
- 城市轉化 → 移除
- 電力管理 → 你的電力
- 大型資產 → 大型物件
- 前期高耗 → 這幾天特別耗
- 第一週 / 適應期 / 終局時程 → 不作玩家可見系統名稱
- 公共庫存 → 你和你認識的人的庫存

## 13. Disabled action 規則

任何 disabled 按鈕必須有可見的前景原因：

- 直接在按鈕下顯示阻擋原因。
- 明示缺少的資源／設備／條件。
- 若有合理下一步，提供直達操作。
- tooltip 只能補充，不能是唯一資訊來源。

## 15. QA 不變條件

- 維持 1920×1080 desktop 三欄優先與小螢幕 reflow。
- 不使用 global transform scale。
- fog 未知地點不得洩漏 true name、圖片、描述、資源、人口、大型物件、NPC。
- scout 只揭露 identity / 公開標籤，不等於 reward / search。
- quick search 與 full itinerary 必須維持不同情報深度。
- 夜間多站行程、路線、人力、Gantt、cargo、重量／體積／fixed-point depth 不得因本次 UI 重構被破壞。
- 不使用電子 beep、chiptune、arcade、terminal 音效。
- 不在未實際執行的情況下宣稱 browser / Playwright / Node QA 已通過。
